# Patrol City (academy/) — working rules

Standing rules from the owner:
- **Fun comes first.** The game has to be very fun and hold players' attention (owner's call, 2026-11-22). Judge every feature by that: learning should be play, not interrupt it, and a feature that teaches but bores gets reworked or cut.
- **Gameplay must be extremely satisfying** (owner's call, 2026-11-27): every action the player takes answers back right away, in picture, sound and (on phones) a buzz, scaled to how much it matters; rewards travel to the meter they fill; nothing important happens silently.
- **The goal is always 10 out of 10** (owner's call, 2026-11-22). Good enough is not done. Each feature is finished only when it meets the 10/10 bar for its area in the RPG Design Reference doc ("What 10 out of 10 means"). If it ships below the bar, say so and list what is left.
- **Every piece is complementary and intentional** (owner's call, 2026-11-22). The core loop is: drive the city, take a call, choose how to handle it, the city remembers, your career grows. Before building anything, name which part of the loop it serves and which two other systems it feeds or reads from, and wire both in the same push. Something that connects to nothing gets merged or cut. Reuse existing systems (squad, co-op, case board, storyteller) instead of adding parallel ones.
- **Every feature ships with an optimization pass.** New features must leave the game at least as fast as before: measure before/after, and pair each feature with a speed-up (cache it, draw it once, move it off the main thread, or do it less often). Never trade visual quality for speed.
- **Don't break the game.** Before pushing: syntax-check every touched module with `node --input-type=module --check < file.js` (plain `node --check` misses errors here), run `tests/run.sh changed` (only the tests that exercise what changed; core files add the quick set), and look at screenshots of anything visual. If it passes, push live. The full regression suite then runs on GitHub (`.github/workflows/regression.yml`, 8 machines, about 5 minutes); check its result and fix anything it finds (owner's call, 2026-11-21, replacing the local full run).
- PvP and co-op are training scenarios with sim rounds only, never live fire. Don't reward bad habits or illegal activity; pursuits, arrests and use of force follow policy (reward terminating risky pursuits, safe distance, radio discipline, de-escalation).
- **Free choice, real consequences** (owner's call, 2026-11-26): the game may offer the ethically wrong choice (corruption, dishonesty, excessive force, misuse of the job), but it never pays off. Consequences follow the discipline ladder in `conduct.js` (reprimand and debuff, gear taken, demotion and suspension, termination, arrest), and a fired or arrested cadet can reload the start of that shift or start over keeping every fact they learned.
- **Specialty units are earned** (owner's call, 2026-11-26): every cadet starts in Patrol; a unit takes its lead's bar (rank, standing, a street stat), two quests and a tryout (or a transfer for an exceptional record), all in `units.js`. Earned units can be switched freely.
- At most 3 quiz questions per interaction; longer runs are split into saved stages, and the player can walk away from any interaction.
- Quiz options must be similar in length and content; the right answer must not be obvious.
- **Everything is made from scratch.** No third-party fonts, icon sets, emoji art, images, sounds or music. Text uses the game's own fonts (Meridian / Meridian Text, built by `tools/makefont.py`); emoji in strings are drawn as the game's own icons (`academy/icons.js`, add a design or a MAP entry for any new emoji); music is composed in `scoredata.js` and rendered with `tools/render-score.js`.
- Push live in batches of two or three features (owner's call, 2026-11-21), one test cycle per batch (GitHub Pages); `database.rules.json` deploys automatically via `.github/workflows/deploy-rules.yml` when it changes.
- The site deploys through `.github/workflows/pages.yml` (owner's call, 2026-11-25): `tools/build-site.sh` builds a minified copy (esbuild, file by file, imports unchanged), the quick set runs against that copy (`ROOT=_site tests/run.sh quick`), and only a passing build goes live. Source files are never minified. Read esbuild's warnings when building locally: they caught a duplicate host key and a reassigned const.
- **What we protect** (decides ties; checked before each phase): three themes only; partners first; the policy spine; made from scratch; a city that remembers; the academy is the frame; the art guide (one light, one line). Details in `STYLE.md`.
- **One style guide.** `STYLE.md` holds the art, voice and music guides together. Check every new feature against all three before it ships; `node tests/tvoice.js` checks the main characters' voices.

Architecture notes:
- Feature modules export `installX(H)` and get a host object from `game.js` (POL, EP, ON, FEEL, SAFE, NG, PREM, COOP...).
- Rendering: depth-sorted `list` of `{d, f}`; sprites are cached (personFast, drawPropFast, vehicleFast, dogFast, label); sprite resolution `RES` follows on-screen scale; ground goes through a sliding screen buffer; buildings can be painted in `sprw.js` (worker).
- Regression tests live in `tests/` (`tests/run.sh quick|full|changed|<names>`, `SHARD=i/N` to split). After adding a test, run `node tests/mkmap.js` so `changed` knows which modules it covers. Wait for elements or conditions, never on fixed pauses alone.
- Local test server: `cd live-drill && python3 -m http.server 8765`, open `/academy/?mock&skiptitle` (test saves need `seenCine: 1, tutDone: 1`).
